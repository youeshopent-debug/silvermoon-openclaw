## 1. 用户反馈分析

### 1.1 现状回顾

| 问题 | 根因 | 严重度 |
|------|------|--------|
| 只是卡片列表换皮 | 当前 cultivation.html 功能完整但视觉上 = 带背景色的卡片矩阵，与 index.html Agent 网格无本质区别 | ★★★★ |
| 缺少"修炼场"的沉浸感 | 页面叫"修炼场"但看起来像 Grafana 面板，场景主题仅停留在配色 + 命名上 | ★★★★★ |
| 状态感知靠读文本 | 在线/离线/挂机/异常靠文字标签和圆点区分，没有"一眼感知"的空间位置映射 | ★★★★ |
| 交互停留在工具层面 | 点击→Modal 只是信息展示，没有"走入这个区域看到这个弟子"的叙事感 | ★★★☆ |
| 动画几乎为零 | 只有 hover 和 fadeIn，缺少活的氛围（漂浮、粒子、灵力波动） | ★★★★ |

### 1.2 Star-Office-UI 可借鉴的点

Star-Office-UI 核心亮点 & 我们如何取其精华：

#### 三区映射对比

| Star-Office-UI 分区 | 对应修炼场区域 | 映射逻辑 |
|--------------------|--------------|---------|
| 🛋️ **休息区** (Rest Zone) | **练功区** (active) | 对应 Star-Office 的"有人在做事"区域 → 我们的 Agent 正在工作中 |
| 💼 **工作区** (Work Zone) | **休息区** (idle) | 对应 Star-Office 的"核心工位"区域 → 我们的 Agent 闲置待命，如同工位上的喘息间隙 |
| 🐛 **Bug 区** (Bug Zone) | **闭关窟** (error) | 对应 Star-Office 的"出问题隔离区" → 我们的异常 Agent 入窟闭关修复 |

**核心设计理念**：Star-Office-UI 用"人在哪=什么状态"的空间映射实现零阅读成本的状态感知，我们继承这一理念，但将分区维度从**状态**升级为**阵营** → 三阵营分区（OC蓝左/TR金中/CC紫右），每个阵营内部再按状态纵向排列。

| Star-Office-UI 做法 | 我们借鉴什么 | 舍弃什么 |
|---------------------|-------------|---------|
| Agent 在不同区域走动 | **空间分区概念**：Agent 按阵营分布在场景的左/中/右三列 | 像素角色动画 → 改为更精致的光晕/符号/粒子表示 |
| 3 区映射（休息区/工作区/Bug 区） | **区域化状态映射启发**：但我们从"按状态分区"升级为"按阵营分区，阵内按状态排列" | Canvas 像素渲染 → 纯 CSS/SVG 渲染 |
| 状态气泡显示当前动作 | **浮动标签**：Agent 头顶浮动显示状态 + 最后原因 | 像素对话框 → 现代毛玻璃浮动标签 |
| 视觉上"一眼看出谁在做什么" | **空间即状态**：抬头扫一眼阵营色块就知道各派系健康度 | 不采用像素美术风格 |

### 1.3 核心洞察

> **修炼场的本质不是监控仪表盘，而是一幅活的宗门景象**。
> 用户打开页面想看的是：弟子们各在其位、各司其职、一派欣欣向荣（或知道谁出了岔子需要"下山"）。
> 不要做成"控制台"，要做成"一幅画"。

## 2. 重新设计目标

1. **空间即状态** → Agent 的位置直接映射其运行状态，一眼可感知整体健康度
2. **沉浸式叙事** → 页面不再是一组卡片，而是一幅中国风+科技感的修炼场景画面
3. **精致动画** → 每个 Agent 有呼吸/悬浮/灵力波动等微妙动画，状态切换有过渡效果
4. **业务逻辑零损失** → 保留 17 Agent 映射、状态判断、轮询、降级、Modal、活动日志全部现有功能
5. **响应式** → 从 1366px 笔记本到 4K 大屏均呈现完整场景
6. **纯 CSS/SVG 渲染** → 不用 Canvas，纯 HTML/CSS/JS，可维护性优先

### 3.2 场景层次

从远到近共 5 层（CSS z-index 分层渲染）：

| 层 | 内容 | 实现方式 | 说明 |
|----|------|---------|------|
| L0 背景 | 深空渐变 + 雾气 | CSS gradient + animation | #0A0A0A → 深蓝紫渐变 |
| L1 远景 | 山峦剪影/流云 | SVG inline 或 CSS clip-path | 静态 + 微妙飘动 |
| L2 场景 | 地面平台/莲花台/剑气阵 | CSS shape + box-shadow + 渐变 | 承载 Agent 的区域底座 |
| L3 Agent | 各区域中的 Agent | div + CSS | 浮动卡片形态，带光晕 |
| L4 UI 层 | 统计数据/过滤/活动日志 | 半透明毛玻璃面板 | 不遮挡场景主视觉 |

## 4. 场景区域设计

### 4.1 三阵营分区（架构核心变更 v2）

**核心变更**：从 v1 的"按状态分四区"重构为"按阵营分三列，阵内按状态纵向排列"。

#### 阵营分区总表

| 阵营 | 阵营色 | 位置 | Agent 列表 | 视觉主题 |
|------|-------|------|-----------|---------|
| **OC** (OpenClaw) | #00D4FF 蓝 | 左侧 | 银月、李长寿、韩立、墨影、雅妃、许青、紫灵 (×7) | 寒冰灵气/蓝色法阵 |
| **TR** (Trading) | #F59E0B 金 | 中央 | 药老、萧炎、紫妍、紫研、美杜莎 (×5) | 金色莲台/丹炉之光 |
| **CC** (ControlCenter) | #CC44FF 紫 | 右侧 | 寻宝鼠、小医仙、海波东、蓝灵儿 (×4) | 紫色剑气/雷纹禁制 |

#### 阵内状态纵列（每阵营通用）

每个阵营区域内，Agent 从上到下按状态纵向排列：

| 纵向层级 | 映射状态 | 视觉表现 | 位置 |
|---------|---------|---------|------|
| **练功层** | active | 灵力光晕，脉动活跃 | 阵营列顶部 |
| **休息层** | idle | 暖黄光晕，悬浮平稳 | 阵营列中部 |
| **闭关层** | error | 红光闪烁，封印纹理 | 阵营列中下部 |
| **已下山** | offline | 灰色褪色，半透明 | 阵营列底部 |

> **设计意图**：用户第一眼看到的是三大色块（蓝/金/紫）—— 直观了解各派系整体状况。再纵向扫视各阵营内部的 active/idle/error 分布，精度到单个 Agent。空间即信息，一目了然。

### 4.2 阵营区域承载 Agent 数量

| 阵营 | Agent 总数 | 布局规则 |
|------|-----------|---------|
| OC 左 (蓝) | 7 | 状态纵列 × 1～2 列，从上到下 active→idle→error→offline |
| TR 中 (金) | 5 | 状态纵列 × 1 列，同上 |
| CC 右 (紫) | 4 | 状态纵列 × 1 列，同上 |
| 底部离线栏 | 0～7 | 三阵营各自的 offline Agent 下沉至底部横条，仍带阵营色 |

### 4.3 Agent 在场景中的表示

每个 Agent 不再是一张扁平卡片，而是"修炼中的弟子"形态：

```
┌────────────┐
│ 🟢          │  ← 状态光晕 (颜色/脉动对应状态)
│  李长寿     │  ← 名字 (发光文字)
│  ───────    │
│  心跳 247   │  ← 紧凑指标 (hover 展开)
│  最后: 5秒前 │
│             │
│  ═══════    │  ← 根基光环 (阵营色)
└────────────┘
```

**视觉特征**：
- 每个 Agent 是**圆形光晕 + 名字竖排**，类似修仙小说中的"本命光球"
- 状态不同 → 光晕颜色/大小/动画不同
- 阵营不同 → 光晕边缘色不同
- Hover 时展开显示详细指标（心跳、在线时长、最后原因）
- 点击弹出 Modal（复用现有逻辑）

  display: flex;
  align-items: center;

## 8. 技术约束

| 项目 | 说明 |
|------|------|
| 渲染方式 | **纯 HTML/CSS/JS**，无 Canvas，无第三方可视化库。不取 Phaser Canvas 像素方案（Star-Office-UI 用 Phaser 做像素风，我们放弃），改用 **纯 CSS Cultipunk 高精渲染** — 利用 CSS gradient + box-shadow + backdrop-filter + SVG inline 实现 cultipunk 风格的高精度场景渲染，兼顾视觉质感与 DOM 可维护性 |
| 场景实现 | CSS gradient + box-shadow + SVG inline 构建多层场景 |
| 粒子系统 | CSS @keyframes 多点动画，不引入粒子库 |
| API 端点 | `/api/status` (现有), `/api/heartbeats` (现有) |
| 刷新频率 | 5 秒轮询 (现有) |
| 降级方案 | API 不可用时自动 fallback 到演示数据 (现有) |
| 状态映射 | 沿用现有：active (connected + hbAge<70s) / idle (connected + hbAge>=70s) / error (lastReason=error/deviation) / offline (其他) |
| 动画性能 | 优先使用 transform/opacity 动画（GPU 合成），避免 layout 触发 |
| 代理/网络 | 外网请求走 `127.0.0.1:7890` |
| 浏览器兼容 | Chrome 最新版，可依赖 CSS Grid/Flexbox/backdrop-filter/keyframe |
